# 小额贷智能客服 Agent 学习知识清单

## 1. 使用方式

这份清单面向有 Java 后端经验、准备转向 AI Agent 应用开发的工程师。学习目标不是推导大模型训练算法，而是能够：

1. 解释 Agent 为什么这样设计；
2. 独立实现 RAG、Tool Calling、记忆、状态机和人工接管；
3. 定位错误回答、错误工具调用和性能问题；
4. 在面试中说明安全、可靠性、评测和工程取舍。

优先级：

- P0：开发 MVP 前必须掌握；
- P1：完成 MVP 过程中掌握；
- P2：项目增强或面试进阶。

学习每个主题时至少留下一个可验证产物：代码、测试、设计说明、评测报告或故障复盘。

## 2. 大模型应用基础

### 2.1 Token 与上下文窗口（P0）

需要掌握：

- Token 与字符、单词之间的关系；
- 系统消息、用户消息、检索内容、工具定义都会占用上下文；
- 上下文窗口、最大输出长度和截断风险；
- 输入/输出 Token 对延迟和成本的影响；
- 为什么对话不能无限追加历史消息。

项目实践：

- 统计每次请求输入、输出 Token；
- 对长会话实现最近消息＋结构化摘要；
- 设置最大检索上下文和最大回答长度。

面试要能回答：为什么不能把整个知识库或全部历史对话放入 Prompt？

### 2.2 Prompt 角色与指令层级（P0）

需要掌握：

- System、User、Assistant、Tool 消息的职责；
- 指令、业务数据和检索证据的隔离；
- Few-shot 示例的用途和风险；
- 结构化输出与 JSON Schema；
- Temperature 等参数对稳定性的影响。

项目实践：

- 为意图分类、风险分类、回答生成分别维护提示词；
- 对提示词进行版本管理；
- 使用 Java 类型接收结构化分类结果；
- 对非法结构实现有限重试和安全降级。

### 2.3 Embedding 与语义相似度（P0）

需要掌握：

- Embedding 的用途；
- 向量维度、余弦相似度、内积和欧氏距离；
- 为什么语义相近不代表事实正确；
- Embedding 模型更换后为什么需要重新建索引；
- 中文、领域词和长文本对召回的影响。

项目实践：

- 对同义问法、产品编码和易混淆产品做相似度实验；
- 记录模型名称、维度和索引版本；
- 比较纯向量检索与混合检索结果。

### 2.4 模型能力边界（P0）

需要掌握：

- 幻觉、非确定性和知识时效性；
- 模型适合语言理解与生成，不适合作为业务事实源；
- 金额、状态、权限和状态迁移应由确定性程序处理；
- 模型输出“像真的”不等于可执行。

项目实践：

- 强制账单金额来自业务工具；
- 无证据时拒答；
- 对模型回答进行事实与敏感信息检查。

## 3. Spring AI

### 3.1 核心抽象（P0）

需要掌握：

- `ChatModel`、`ChatClient`；
- `Prompt`、Message 和 Advisor；
- `EmbeddingModel`；
- `Document`、`VectorStore`、`SearchRequest`；
- Tool Calling 的注册和执行；
- 同步调用与流式调用。

项目实践：

- 使用配置切换模型供应商；
- 实现一个结构化意图分类调用；
- 实现一个流式知识回答接口；
- 接入 pgvector；
- 注册账单查询工具。

### 3.2 模型适配与配置（P1）

需要掌握：

- OpenAI 兼容 API 的基本结构；
- API Key、Base URL、模型名和超时配置；
- 不同模型的工具调用和结构化输出差异；
- 配置外置和密钥管理；
- 模型升级后的回归测试。

项目实践：

- 提供 `.env.example`，不提交真实密钥；
- 用 Spring Profile 切换 Mock 与真实模型；
- 至少对比两个模型在同一评测集上的效果。

### 3.3 Spring AI 边界（P1）

需要掌握：

- 框架简化模型接入，但不会自动解决权限、安全和业务一致性；
- Advisor、Memory 和 Tool 的调用顺序；
- 什么时候使用框架组件，什么时候自研状态机；
- 避免业务逻辑被 Prompt 和框架隐式行为隐藏。

面试要能回答：项目为什么使用 Spring AI，但没有把全部 Agent 编排交给框架？

## 4. Agent 核心知识

### 4.1 Agent 与普通聊天机器人的区别（P0）

需要掌握：

- 普通问答、工作流、Agent 的区别；
- Agent 的状态、观察、决策、动作和结果；
- 确定性工作流与自治推理的取舍；
- 为什么金融客服更适合受控 Agent。

### 4.2 状态机编排（P0）

需要掌握：

- 状态、事件、迁移、守卫条件和终态；
- 节点幂等和失败恢复；
- 前置状态检查；
- 循环次数和工具调用次数上限；
- 状态持久化与断点恢复。

项目实践：

- 实现输入检查、意图分类、风险分类、认证检查、检索、工具、生成和转人工节点；
- 为每次状态迁移写单元测试；
- 工具连续失败后进入人工终态；
- SSE 断线后能够根据 sessionId 恢复。

### 4.3 意图与实体识别（P0）

需要掌握：

- 意图分类与槽位填充；
- 规则、小模型和大模型的组合；
- 多轮指代消解；
- 置信度、澄清问题和兜底意图；
- 高风险分类为何关注召回率。

项目实践：

- 定义稳定的意图枚举；
- 使用结构化输出返回意图、实体和置信度；
- 对“它”“这一笔”等指代进行多轮测试；
- 投诉场景用规则＋模型双通道识别。

### 4.4 Tool Calling（P0）

需要掌握：

- 工具描述、参数 Schema 和返回值；
- 工具选择与参数抽取；
- 只读工具与写工具的风险差异；
- 超时、重试、幂等和补偿；
- 为什么工具返回 DTO 而不是数据库实体；
- 为什么授权不能依靠模型。

项目实践：

- 实现申请进度、账单、支付、结清试算和工单工具；
- 从 SecurityContext 获取 customerId；
- 对 loanId 做资源归属校验；
- 为工单创建加入幂等键；
- 记录脱敏工具输入、结果码和耗时。

### 4.5 记忆与上下文管理（P1）

需要掌握：

- 短期消息、结构化槽位、会话摘要和长期事实的区别；
- 滑动窗口与摘要压缩；
- 记忆污染和错误事实延续；
- 敏感数据最小化；
- 业务状态必须重新查询。

项目实践：

- Redis 保存短期会话；
- 摘要只保留目标、实体、已完成动作和待办；
- 贷款和账单每次通过工具重新获取。

### 4.6 Human-in-the-loop（P0）

需要掌握：

- 哪些场景必须人工接管；
- 转人工触发条件；
- Agent 到坐席的上下文交接；
- 人工修改和最终决定如何审计；
- 客户主动要求人工时的体验设计。

项目实践：

- 投诉、冒名、隐私泄露、减免协商直接转人工；
- 自动生成客观摘要；
- 向坐席展示认证状态、工具结果和转接原因。

### 4.7 Multi-Agent（P2）

需要理解但首版不必实现：

- Supervisor、Router、Planner/Executor 模式；
- 多 Agent 通信、共享状态和权限边界；
- 延迟、成本、死循环和责任不清问题；
- 什么情况下拆分专用 Agent 才有收益。

面试观点：业务边界清晰且高风险的客服流程，单 Agent 状态机通常比多 Agent 更容易审计和测试。

## 5. RAG 工程

### 5.1 文档解析与切分（P0）

需要掌握：

- PDF、Markdown、表格和扫描件的解析差异；
- 固定长度切分、递归切分和语义切分；
- chunk size、overlap 与完整语义的平衡；
- 标题路径和表格上下文保留；
- 文档去重与内容校验和。

项目实践：

- FAQ 按一问一答切分；
- 产品条款按标题层级切分；
- 每个 chunk 保存文档、章节、产品和版本。

### 5.2 检索与重排（P0）

需要掌握：

- 关键词检索、向量检索和混合检索；
- Top-K、相似度阈值；
- BM25/全文检索基本思想；
- RRF 融合；
- Cross-Encoder/Reranker；
- Query Rewrite 与多轮问题改写。

项目实践：

- PostgreSQL FTS 与 pgvector 各召回 Top 20；
- 使用 RRF 合并；
- 重排后保留 Top 3～5；
- 记录每一步召回结果以便排错。

### 5.3 元数据与版本治理（P0）

需要掌握：

- 产品、地区、渠道、受众和生效时间过滤；
- 草稿、审核、发布、失效生命周期；
- 新旧版本冲突；
- 内部知识与对客知识隔离。

项目实践：

- 设计两个规则相近但期限不同的产品；
- 发布新版本并验证旧版本不再召回；
- 客户端无法检索 INTERNAL 文档。

### 5.4 RAG 失败分析（P1）

能够区分：

- 没有正确知识：知识缺失；
- 正确知识未召回：检索问题；
- 正确知识排名太低：重排问题；
- 上下文正确但回答错误：生成问题；
- 使用旧知识：元数据或发布流程问题。

面试时不要笼统地说“优化 Prompt”，要能够根据链路定位责任环节。

## 6. Java 与后端工程能力

### 6.1 Spring Boot 与模块化设计（P0）

需要掌握：

- Controller、Application Service、Domain Service、Repository 分层；
- 模块边界和依赖方向；
- DTO 与领域实体隔离；
- 统一异常和错误码；
- 配置与 Profile 管理。

项目实践：

- Agent Tool 只依赖应用服务；
- 业务模块不依赖具体大模型；
- 模型适配器可以替换。

### 6.2 Spring Security（P0）

需要掌握：

- Authentication、SecurityContext、Filter Chain；
- JWT 的签发、校验和过期；
- RBAC 与资源级授权；
- 登录认证与二次认证；
- 前端传入身份为什么不能作为授权依据。

项目实践：

- customerId 只从 SecurityContext 获取；
- Tool 和 Service 双层保护敏感操作；
- 对其他客户 loanId 的请求返回统一安全错误。

### 6.3 幂等、事务和并发（P0）

需要掌握：

- 唯一索引、幂等表和请求号；
- 数据库事务边界；
- 乐观锁与悲观锁；
- 超时重试可能导致的重复写；
- Outbox/消息最终一致性的基本思想。

项目实践：

- 工单创建使用幂等键；
- Agent 恢复时不重复执行成功的写工具；
- 并发测试验证只生成一张工单。

### 6.4 WebFlux 与 SSE（P1）

需要掌握：

- SSE 与 WebSocket 的区别；
- Reactor 的 `Mono`、`Flux` 与背压基本概念；
- 流式模型响应；
- 客户端断连和重连；
- 不阻塞事件循环线程。

项目实践：

- 定义 status、answer_delta、business_card、completed 和 error 事件；
- 不向前端发送模型隐藏推理过程；
- 用 lastEventId 或消息序号处理重连。

### 6.5 Resilience4j（P1）

需要掌握：

- Timeout、Retry、Circuit Breaker、Rate Limiter、Bulkhead；
- 哪些错误适合重试；
- 为什么写操作不能盲目重试；
- 降级路径和人工兜底。

项目实践：

- 模型超时进入固定提示；
- 账单系统失败时不回答金额；
- 向量库故障时保留人工入口。

## 7. 数据库与向量存储

### 7.1 PostgreSQL（P0）

需要掌握：

- 表、索引、事务和唯一约束；
- JSONB 适用场景；
- `numeric` 存储金融金额；
- `timestamptz` 与时区；
- 全文检索的 tsvector/tsquery；
- Flyway 迁移。

### 7.2 pgvector（P0）

需要掌握：

- vector 类型和维度；
- 精确检索与近似索引；
- HNSW/IVFFlat 的概念与取舍；
- 距离函数与索引匹配；
- 元数据过滤对性能的影响。

项目实践：

- 建立知识切片向量列和索引；
- 使用 EXPLAIN 检查查询；
- 比较不同 Top-K 和阈值的效果。

### 7.3 Redis（P1）

需要掌握：

- 会话缓存、TTL 和过期；
- 限流；
- 分布式锁的适用与限制；
- 缓存与数据库事实的一致性。

项目实践：

- 只保存短期会话和认证状态；
- 不把 Redis 中的聊天摘要当作贷款事实源。

## 8. 安全与合规

### 8.1 常规应用安全（P0）

需要掌握：

- 身份认证、授权、最小权限；
- OWASP 常见风险；
- SQL 注入、XSS、CSRF、SSRF；
- 密钥管理；
- 日志脱敏和审计；
- 文件上传安全。

### 8.2 LLM 应用安全（P0）

需要掌握：

- Prompt Injection 和间接注入；
- 敏感信息泄露；
- 不安全工具调用；
- 过度授权；
- 不安全输出处理；
- 模型拒绝并不能替代后端权限控制。

项目实践：

- 建立至少 20 条攻击测试；
- 检索内容标记为不可信数据；
- 工具使用参数白名单和服务端授权；
- 前端展示前对模型输出进行处理。

### 8.3 金融客服边界（P0）

需要理解：

- 消费者知情权、公平交易权和信息安全权；
- 利率、费用、期限和违约责任应清晰披露；
- 不能承诺一定放款或诱导过度借贷；
- 催收不得威胁、骚扰或向无关第三人披露债务；
- 自动化重大决定需要透明、可解释和人工复核机制；
- 个人信息处理遵循合法、正当、必要和最小范围。

项目实践：

- 对违规催收、冒名贷款和隐私泄露设置最高优先级；
- 自动审批、自动定价和真实催收不进入项目首版；
- 对客知识需要状态和审核人。

## 9. 测试、评测与可观测性

### 9.1 Java 测试（P0）

需要掌握：

- JUnit 5、Mockito；
- Spring Boot 集成测试；
- Testcontainers；
- 参数化测试；
- 并发和幂等测试；
- 测试替身模拟模型响应。

### 9.2 Agent 评测（P0）

需要掌握：

- Golden Dataset；
- 意图准确率、高风险召回率；
- 工具选择与参数准确率；
- RAG Recall@K、MRR；
- Faithfulness/忠实度；
- 无答案拒答率；
- LLM-as-a-Judge 的优点与局限。

项目实践：

- 建立不少于 150 条测试数据；
- 金额、状态、权限使用程序断言；
- 表达质量才使用模型裁判；
- 每次修改模型、Prompt 或知识后跑回归。

### 9.3 可观测性（P1）

需要掌握：

- 日志、指标和 Trace 的区别；
- OpenTelemetry 基本概念；
- 模型耗时、首字延迟、Token 和成本；
- 检索与工具调用的节点级追踪；
- 不能记录隐藏推理和明文敏感信息。

项目实践：

- 每次对话生成 traceId；
- 可定位错误发生在分类、检索、工具还是生成；
- 输出版本化评测报告。

## 11. 小额贷业务知识

### 11.1 贷款生命周期（P0）

需要掌握：

```text
产品咨询 → 申请 → 资料补充 → 审批 → 签约
→ 放款 → 还款计划 → 正常还款/提前结清
→ 逾期处理 → 结清 → 投诉与售后
```

### 11.2 核心业务对象（P0）

- 客户 Customer；
- 产品 LoanProduct；
- 申请 LoanApplication；
- 合同/贷款 Loan；
- 还款计划 RepaymentPlan；
- 支付流水 PaymentRecord；
- 结清试算 SettlementQuote；
- 客服工单 ServiceTicket。

### 11.3 金额知识（P1）

需要掌握：

- 本金、利息、费用和应还总额；
- 年化利率与期利率；
- 等额本息、等额本金、先息后本的概念；
- 逾期金额和提前结清试算；
- 为什么使用 BigDecimal、舍入规则和统一计算日。

项目中可以实现简化且明确的试算规则，但必须在文档和测试中说明假设，不能让大模型计算。

### 11.4 客服与催收边界（P0）

- 客服解释事实和提供办理入口；
- 协商减免需要有权限的人工处理；
- 投诉摘要要客观，不自行认定责任；
- 催收相关内容必须使用合规审核话术；
- 不向债务无关第三人披露贷款信息。

## 12. 建议学习顺序

### 阶段一：能调用模型，预计 2～3 天

- Token、Prompt、结构化输出；
- Spring AI ChatClient；
- 同步与 SSE 流式回答；
- 模型配置和密钥管理。

产物：一个支持结构化意图分类和流式回答的 Spring Boot Demo。
