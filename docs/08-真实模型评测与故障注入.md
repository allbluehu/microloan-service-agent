# 真实模型评测与故障注入

## 1. 联调完成判据

一次请求只有同时满足以下条件，才算真实模型意图分类成功：

- HTTP 对话接口返回预期业务结果；
- `INTENT_CLASSIFIER` Trace 的 `source=MODEL`；
- Trace 的 `modelVersion` 为实际 GLM 模型，`promptVersion` 为当前提示词版本；
- 模型输出通过严格 JSON、受控标签及置信度门槛。

若 Trace 为 `source=RULE`，表示业务降级成功，但不能作为真实模型成功证据。

## 2. 版本化评测报告

真实评测默认关闭，避免普通测试和 CI 消耗模型额度。加载 `.env` 后显式运行：

```bash
set -a
source .env
set +a
REAL_MODEL_EVAL_ENABLED=true mvn -Dtest=RealModelIntentEvaluationTest test
```

报告写入 `target/evaluation/intent-v4--<model>--<UTC时间>.json`，包含：

- 报告格式、模型、提示词和数据集 SHA-256 版本；
- 准确率、协议通过率、429 数量、供应商错误数和 P95 延迟；
- 每条样本的预期意图、实际意图、置信度、耗时和结果状态。

默认准确率门槛为 90%，协议通过率门槛为 95%。可使用
`REAL_MODEL_EVAL_MIN_ACCURACY`、`REAL_MODEL_EVAL_MIN_PROTOCOL_RATE`、
`REAL_MODEL_EVAL_INTERVAL_MS` 和 `REAL_MODEL_EVAL_TIMEOUT_SECONDS` 调整。

## 3. 故障注入覆盖

普通测试必须保持离线、确定且不依赖 GLM。覆盖边界如下：

| 故障 | 预期行为 | 覆盖位置 |
|---|---|---|
| HTTP 429 / 瞬时异常 | 回退本地规则 | `IntentClassifierTest` |
| 非法 JSON | 拒绝模型输出并回退规则 | `IntentClassifierTest` |
| 低于 0.75 | 拒绝模型输出并回退规则 | `IntentClassifierTest` |
| 整体调用超时 | 中断任务并记录 timeout 指标 | `ModelCallExecutorTest` |
| 连续失败 | 熔断并立即拒绝后续调用 | `ModelCallExecutorTest` |
| 并发容量耗尽 | 不排队，立即回退 | `ModelCallExecutorTest` |
| Trace 数据库写入失败 | 不覆盖正常业务结果 | `ChatVerticalSliceIntegrationTest` |

真实 GLM 的 429 和网络波动由版本化报告统计，不作为离线测试的外部依赖。
