# 真实模型评测与故障注入

## 1. 联调完成判据

一次请求只有同时满足以下条件，才算真实模型意图分类成功：

- HTTP 对话接口返回预期业务结果；
- `INTENT_CLASSIFIER` Trace 的 `source=MODEL`；
- Trace 的 `modelVersion` 为实际供应商模型，`promptVersion` 为当前提示词版本；
- 模型输出通过严格 JSON、受控标签及置信度门槛。

若 Trace 为 `source=RULE`，表示业务降级成功，但不能作为真实模型成功证据。

## 2. 版本化评测报告

真实评测默认关闭，避免普通测试和 CI 消耗模型额度。加载 `.env` 后显式运行：

```bash
set -a
source .env
set +a
REAL_MODEL_EVAL_ENABLED=true mvn -Dtest=RealModelIntentEvaluationTest test
```

报告写入 `target/evaluation/intent-v4--<model>--<UTC时间>.json`，新格式为 `intent-evaluation-v2`。
采集使用直接 HTTP 单次尝试，不经过线上 `ModelCallExecutor` 的 3 秒预算、重试、熔断或规则回退；因此不能把本报告延迟当作业务接口延迟。

### 2.1 原始预测与失败记录

- 每个样本有稳定唯一 `id`；新增 ID 会改变数据集 SHA-256，但未改变既有问题和标签。
- 高风险和复合请求保留为 `SKIPPED_HIGH_RISK` / `SKIPPED_COMPOSITE`，不计入模型请求分母。
- 所有协议合法结果保存 `actualIntent/confidence/correct`，包括低于 0.75 的结果，状态均为 `PROTOCOL_VALID`。
- 失败分别记录 `RATE_LIMITED`、`HTTP_ERROR`、`TIMEOUT`、`TRANSPORT_ERROR`、`RESPONSE_INVALID`（响应外壳错误）、`PROTOCOL_INVALID`（模型输出不合法）。
- 每次尝试都保存耗时，包括失败；不保存原始响应、凭据或异常正文。
- 记录本地 `ruleIntent`，可模拟未采纳模型时的规则标签替换；这不是完整 Agent 或线上熔断时序评测。
- 保存模型、提示词、数据集哈希、采纳阈值、超时、调用间隔、单次尝试配置；`REAL_MODEL_EVAL_CODE_VERSION` 可提供本次代码版本，未提供则明确标记 `unrecorded`。

### 2.2 指标口径与门禁

令 N 为实际尝试数（不含跳过样本），H 为 HTTP 2xx 数，V 为协议合法数，C 为协议合法且分类正确数。
在某阈值下，A 为被采纳数，K 为被采纳且分类正确数。

| 字段 | 口径 |
|---|---|
| `httpSuccessRate` | H / N，HTTP 层成功率，响应外壳仍可能不合法 |
| `protocolSuccessRate` | V / N，全请求获得合法协议结果的比例 |
| `protocolValidRate` | V / H，HTTP 成功响应中的协议合法率 |
| `classificationAccuracy` | C / V，不应用采纳阈值的分类准确率 |
| `acceptanceRate` | A / N，阈值下模型采纳率 |
| `acceptedAccuracy` | K / A，被采纳模型结果的准确率 |
| `wrongAcceptanceRate` | (A − K) / N，全请求中的错误采纳比例 |
| `requestCorrectRate` | K / N，全请求得到正确且被采纳模型结果的比例 |
| `simulatedFallbackAccuracy` | 采纳模型，否则使用已保存的规则标签；缺少所需规则标签则为 null |

分母为零时返回 JSON `null`，不把零样本视作 100% 正确。P95 明确标为 `p95RecordedLatencyMs`；旧报告缺失失败耗时时会输出警告与缺失数量。

门禁保留环境变量名以兼容现有运行命令：

- `REAL_MODEL_EVAL_MIN_ACCURACY`（默认 0.90）：检查指定阈值下的 `requestCorrectRate`。
- `REAL_MODEL_EVAL_MIN_PROTOCOL_RATE`（默认 0.95）：检查 `protocolSuccessRate`，即合法协议结果占全部请求的比例；v2 不再把低置信度视作协议错误。
- `REAL_MODEL_EVAL_THRESHOLD`（默认 0.75）：本次评测门禁的采纳阈值，不修改线上阈值。
- `REAL_MODEL_EVAL_THRESHOLDS`：本次同时扫描的阈值列表，默认 `0,0.5,0.7,0.75,0.8,0.9,0.95,0.98,0.99,1`。
- `REAL_MODEL_EVAL_INTERVAL_MS`、`REAL_MODEL_EVAL_TIMEOUT_SECONDS`：控制采集节流间隔和直接 HTTP 超时。

全部预测与分析在门禁断言前写入磁盘，失败报告同样可以重算。v1 的 `accuracy/protocolValidRate` 与 v2 的同名概念不应直接混比，必须先核对分母和阈值条件。

### 2.3 离线扫描已有报告（不访问模型）

```bash
INTENT_EVAL_REPORT=target/evaluation/intent-v4--glm-4.6--20260902-071510.json \
INTENT_EVAL_THRESHOLDS=0.5,0.75,0.8,0.95,0.98,0.99,1 \
mvn -Dtest=IntentThresholdAnalysisTest test
```

输出 `target/evaluation/<原报告文件名>.thresholds.json`，原报告不变。派生报告绑定原报告 SHA-256、模型、提示词和数据集版本，可在现有坐席评测看板导入查看。

兼容 v1 的边界：旧版 `PROTOCOL_REJECTED` 混合了协议失败与低置信度，若存在该状态，则低于 0.75 的扫描点标记 `recoverable=false`，相关统计为 null；协议合法总量同样无法完整恢复。旧版没有记录规则预测，不会通过当前规则或样本顺序伪造历史规则结果。原有空 caseId 保持原样。

GLM-4.6 的 20260902 报告没有 `PROTOCOL_REJECTED`，所以可扫描其已保存预测；但合法结果全部集中在 0.95～1.0，无法证明 0.75 优于 0.8。阈值扫描只展示样本上的取舍，不自动选择“最优阈值”；实际选择应在独立调参集上完成，再用未参与调参的验收集验证。

## 3. 故障注入覆盖

普通测试必须保持离线、确定且不依赖外部模型供应商。覆盖边界如下：

| 故障 | 预期行为 | 覆盖位置 |
|---|---|---|
| HTTP 429 / 瞬时异常 | 回退本地规则 | `IntentClassifierTest` |
| 非法 JSON | 拒绝模型输出并回退规则 | `IntentClassifierTest` |
| 低于 0.75 | 拒绝模型输出并回退规则 | `IntentClassifierTest` |
| 整体调用超时 | 中断任务并记录 timeout 指标 | `ModelCallExecutorTest` |
| 连续失败 | 熔断并立即拒绝后续调用 | `ModelCallExecutorTest` |
| 并发容量耗尽 | 不排队，立即回退 | `ModelCallExecutorTest` |
| Trace 数据库写入失败 | 不覆盖正常业务结果 | `ChatVerticalSliceIntegrationTest` |

真实供应商的 429 和网络波动由版本化报告统计，不作为离线测试的外部依赖。

## 4. 真实 Embedding 与混合召回评测

向量评测同样默认关闭。它使用 Testcontainers 创建一次性 PostgreSQL，不修改本地、测试或生产数据库；
测试会导入 10 份 classpath 知识，执行审批、发布和配置的 Embedding 模型索引，然后验证全文＋向量 RRF 召回。

```bash
set -a
source .env
set +a
REAL_EMBEDDING_EVAL_ENABLED=true mvn -Dtest=RealEmbeddingHybridEvaluationTest test
```

完成门槛如下：

- 模型返回维度必须为 1024，与 `VECTOR(1024)` DDL 一致；
- 全部知识切片必须记录 `AI_EMBEDDING_MODEL_NAME` 模型版本并成功写入向量；
- 8 条全文零命中的口语化问题必须由向量路补召回预期文档；
- 产品错配时不得返回其他产品的知识。

报告写入 `target/evaluation/embedding-hybrid--<模型>--<UTC时间>.json`，绑定数据集 SHA-256、
模型、维度、索引切片数、混合召回率和全文未命中补召回数。
