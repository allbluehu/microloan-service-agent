# P1–P2 交付与演示验收

## 本地启动

Java 21、Maven 3.6.3+、Docker 为后端前置条件。前端构建产物已入库，运行演示无需 Node。

```bash
docker compose up -d postgres
mvn spring-boot:run
```

客户入口：`http://localhost:8080/chat.html`。演示客户 `C10001`、密码 `Demo123!`；登录后展开“业务选择与会话摘要”，贷款填 `L10001`。前端不再预填密码。

坐席入口：`http://localhost:8080/support.html`。启动前配置至少 32 字节的 `SUPPORT_API_KEY`；它与 `KNOWLEDGE_ADMIN_API_KEY` 独立，客户 JWT 和知识密钥都不能访问坐席 API。坐席是本地演示用单一服务身份；审计记录状态、脱敏说明和时间，不代表生产多坐席实名审计。

前端源码位于 `web/`。修改后执行：

```bash
npm ci --prefix web
npm run check --prefix web
npm run build --prefix web
```

构建更新 `src/main/resources/static/ui/`，应与源码一并提交。Vue 3 + TypeScript 由 Vite 打包，静态资源由 Spring Boot 提供，未依赖 CDN。

## 固定演示脚本（约 8～10 分钟）

1. 登录，选择 `L10001`，问“我下个月要还多少钱？”：展示处理状态、确定性回答和金额分项卡片。
2. 展开处理过程：检查风险、意图、工具、结果校验、输出护栏的顺序与耗时。没有启用真实模型时，意图来源应为规则。
3. 点赞或选择原因后提交问题反馈，切换历史会话后验证反馈仍可读取。
4. 填写当前试算日期，问“我要提前结清试算”：普通令牌收到二次认证提示；重新输入密码后点击“重试上一条”，显示试算有效期与费用分项。
5. 新会话问“请转人工客服”。坐席工作台显示待接单工单，展开最近对话，填写处理说明后接单，再切换到处理中并结单；重复旧状态更新返回 409。
6. 问知识材料问题并展示引用：前提是已通过知识管理台导入、审批、发布相关文档。未发布或无合格知识时观察拒答。
7. 恢复旧会话：业务选择与近期主题恢复；清除业务选择后再次查询需要重新选择贷款。历史账单金额不会作为新回答依据。
8. 在坐席工作台查看整轮 P95、工具调用结果和模型指标，并导入 `target/evaluation/*.json` 查看版本化评测报告。报告只在浏览器本机解析。

## 接口增量

| 方法与路径 | 权限 | 行为 |
|---|---|---|
| `POST /api/v1/chat/sessions/{sessionId}/stream` | 客户 JWT | 请求体与非流式 messages 接口一致，SSE 返回处理状态和已校验答案 |
| `GET /api/v1/chat/sessions/{sessionId}/context` | 会话所有者 | 已选择实体及最近 100 条消息涉及的至多 5 个主题，不含历史金额 |
| `DELETE /api/v1/chat/sessions/{sessionId}/context` | 会话所有者 | 清除持久化业务槽位，保留历史消息 |
| `GET /api/v1/support/tickets?status=OPEN` | 坐席密钥 | 至多 100 条工单，高优先级优先、同级按创建时间排序 |
| `GET /api/v1/support/tickets/{ticketId}/context` | 坐席密钥 | 通过工单客户与会话联合关联，读取至多 100 条脱敏消息 |
| `POST /api/v1/support/tickets/{ticketId}/transition` | 坐席密钥 | `expectedStatus` 与 `note`；OPEN → IN_PROGRESS → RESOLVED，冲突返回 409 |
| `GET /api/v1/support/metrics` | 坐席密钥 | 白名单聚合指标，无客户、会话、提示词标签 |

### SSE 协议与重试

事件顺序为 `status → answer → done`，业务失败为 `status → error`。`answer` 的 JSON 契约与普通对话响应相同，`error` 为 `code/message/traceId`。连接建立前的鉴权、校验和容量拒绝仍使用普通 HTTP 状态码；连接建立后用 error 事件表达失败。

答案经过 ResultVerifier、输出护栏和消息持久化后才发送；这里是状态与最终结果事件流，不是逐 Token 生成。当前单实例最多 20 路，连接超时 30 秒。断线后不自动重放、不声称支持 `Last-Event-ID`；页面保留原 messageId 供显式重试，工单继续使用领域幂等键。已开始的业务动作可能在断线后完成，客户端应先核对历史再重试。

### 指标口径

- `microloan.agent.round.duration`：认证后整轮编排耗时，包含模型、工具、校验和持久化；`outcome=success/failure`，P95 单位毫秒，累计总时长单位秒。
- `microloan.agent.tool.calls`：受控执行节点调用次数，以 node 区分知识与业务；success、rejected（业务拒绝）、failure（基础设施失败）分开统计。澄清等未返回工具结果的执行记为 skipped。
- `microloan.agent.model.*`：模型调用耗时与成功、失败、超时、容量拒绝、熔断计数。
- `gen_ai.client.token.usage`：Spring AI 根据真实供应商 usage 记录 input/output/total。缺失时显示为尚无指标，不估算为零；不能把三个类型相加当总量。

指标为当前实例内存累计，重启清零，P95 为实例内滑动统计；没有声称提供跨实例监控或持久化账单成本。

## 自动化验证

```bash
mvn test
python3 scripts/offline-report.py
npm run check --prefix web
npm run build --prefix web
npx --prefix web playwright install chromium
npm run test --prefix web
```

已有本机 Chrome 时可用 `PLAYWRIGHT_CHROME=1 npm run test --prefix web`。浏览器测试使用模拟 API 验证页面交互；Java 集成测试使用真实 Testcontainers PostgreSQL 验证权限、状态流转、SSE 身份传播与持久化，不依赖外部模型。

GitHub Actions 在 push/PR 时运行上述回归、检查静态产物与源码一致，并上传 JUnit、离线报告和浏览器失败 Trace。它不访问真实模型。`scripts/offline-report.py` 汇总实际 JUnit 结果和数据集 SHA-256，缺少测试报告或有失败时返回非零状态；坐席评测看板可直接读取该 JSON。

目标供应商的真实意图和 Embedding 评测仍是 P0 待验收事项，不能使用这些离线结果代替。
